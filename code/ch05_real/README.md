# 第5章 ch05_real：自作のコードで実写の料理を学習する

第4章の描画と第5章の学習を、PyTorchで合わせて490行で書いたコードです。COLMAPの結果と写真から3DGSを学習します。勾配の計算は手で書かず、PyTorchの自動微分（autograd）に任せています。PyTorch、NumPy、Pillowが必要です。

```sh
python train_real.py --data data/bowl --out out/run --long-side 300
```

| ファイル | 内容 |
| --- | --- |
| `colmap_read.py` | COLMAPの `sparse/0` にある三つのバイナリ（カメラ、写真ごとの姿勢、点群）を読む |
| `render_real.py` | 描画。投影、タイルへの割り当て、奥行きでの並べ替え、手前からの合成 |
| `train_real.py` | 学習。損失、Adam、密度制御、不透明度のリセット、評価 |
| `train_real.out.txt` | 料理の写真で実行したときの出力 |

[Reconstruction Scenes](https://huggingface.co/datasets/promc/reconstruction-scenes)の料理の写真51枚のうち44枚を使い、225×300画素で30,000反復学習した結果は次のとおりです（RTX 5090）。

- 保持視点7枚のPSNRは23.73dB、SSIMは0.818、粒の数は387,478個です。
- 反復0は、SfMが求めた14,800個の点をそのまま粒にした状態です。
- 保持視点のPSNRは反復3500〜5000の24.4dB前後がいちばん高く、その後は少しずつ下がります。学習に使った44視点のPSNRは、反復5000の29.8dBから最後の36.8dBまで上がり続けます。
- 反復3000の不透明度のリセットの直後に、保持視点のPSNRは5.17dBまで落ち、反復3500で24.39dBに戻ります。
- 学習をやり直しても、61回の評価すべてで値が一致します。

## 3粒のコードに足したもの

[train3d.py](../ch05_train3d/) に足したのは次の四つです。

- **COLMAPの読み込み**：カメラの焦点距離と写真ごとのカメラ姿勢を読み取り、SfMの各点に粒を一つずつ置いて学習を始めます。
- **タイル**：画面を16×16画素に分け、タイルごとに関係する粒だけを重ねます。
- **SH**：色を球面調和関数の係数で持ち、1,000反復ごとに次数を一つずつ上げて3まで使います。
- **密度制御**：複製、分割、削除と、不透明度のリセットです。

損失、学習率、密度制御の値は、本文の「元の実装の既定値」の表に合わせました。違うのは削除の条件で、画面上の半径が20画素を超える粒の削除を省いています。225×300画素の小さい画像では、この基準の意味が変わるからです。

## 要になる四か所

### 投影（render_real.py の project）

式は第4章の投影と同じです。$\Sigma = RSS^\top R^\top$ で三次元の共分散を作り、ヤコビアン $J$ を使って画面上の共分散 $JW\Sigma W^\top J^\top+0.3I$ を求めます。`train3d.py` の `project` との違いは、すべての粒をまとめて計算することです。

- `valid` は奥行きが0.2より大きい粒です。カメラのすぐ前と後ろの粒は、半径を0にして描画から外します（元の実装と同じ0.2）。
- `limit_x`、`limit_y` の行は、視野の1.3倍より外にある粒の $J$ を、そこで止めた位置で求めます（元の実装と同じ）。
- `mid` と `radius` の行は、画面上の共分散の大きいほうの固有値 $\frac{a+c}{2} + \sqrt{\left(\frac{a-c}{2}\right)^2 + b^2}$ から3σの半径を求めます。
- `center` の行は中心を画素の位置に直します。画素の中心は $(i+0.5,\ j+0.5)$ です。

### タイルへの割り当て（render_real.py の assign_tiles）

`x0` から `y1` は、3σの円を囲む正方形が掛かるタイルの範囲です（元の実装の `getRect`）。粒が掛かるタイルの数だけ行を作り、各行にタイルの番号を入れます。そのうえで、まず奥行きで並べ、次に元の順序を保ったまま（`stable=True`）タイルの番号で並べ直すと、第4章のキー（タイル、奥行き）で並べたのと同じ順になります。

学習を終えた粒を保持視点の一つでタイルに割り当てると、最も多いタイルには387,478個のうち8,343個が重なります（第4章の図）。

### 合成（render_real.py の composite）

タイルの256画素に対して、割り当てられた粒を手前から256個ずつ取り出して重ねます。

- `dx` から `power` までの行と `alpha` の行が、重みの式 $\alpha = o \times \exp\left(-\frac{1}{2}\, d^\top \Sigma_{\text{screen}}^{-1} d\right)$ です。
- $\alpha$ を0.99で頭打ちにし、1/255より小さい粒を飛ばすのは、第4章で見た元の実装どおりです。
- 透過率は、$1 - \alpha$ を手前から掛け合わせた累積の積（`cumprod`）で求めます。0.0001を下回った画素はそこで打ち切ります。
- 合成の式 $C = \sum_i c_i \alpha_i T_i$ は、`weight` と色の行列積で計算します。

[tiny.py](../ch04_tiny/) の `pixel` は一画素ずつ `for` で粒をたどっていました。こちらは（タイル、画素、粒）の三つの軸を持つ配列を使い、タイルのすべての画素を一度に計算します。

### 密度制御（train_real.py の densify_and_prune）

`grads` は、画面上の位置の勾配の大きさを足し合わせ、密度制御の間隔（100反復）のうちその粒が画面に入った回数で割ったものです。基準の `GRAD_THRESHOLD`（0.0002）と、複製か分割かを分ける `PERCENT_DENSE`（シーンの広がりの1%）は表の値です。複製では粒のパラメータをそのまま写し、分割では元の粒のガウス分布から二つの位置を選んで、スケールを1.6で割った粒を置きます。最後の `rebuild` は、残る粒にAdamの移動平均を引き継ぎ、足した粒の分は0で初期化します。

## 元の実装の細部

一反復の処理は、本文の説明と元の実装で次のように対応します。

| 本文の説明 | 元の実装の処理 |
| --- | --- |
| カメラを一つ選んで描画する | `render` |
| 写真との差を測る | `l1_loss`、`ssim` |
| 勾配を求める | `loss.backward` |
| 粒を増やす、削る | `densify_and_prune` |
| 不透明度をリセットする | `reset_opacity` |
| パラメータを更新する | `optimizer.step` |

損失は[この一行](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f/train.py#L126)です。密度制御と不透明度のリセットの条件は、[train.pyの164〜174行](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f/train.py#L164-L174)にあります。

- 密度制御は、反復数が500より大きく15,000未満で、100の倍数のときに行います。最初が反復600、最後が反復14,900です。
- 不透明度のリセットも15,000未満の3,000の倍数のときだけなので、通常は四回です。背景を白にした学習では、反復500でも一回リセットします。リセットは[この一行](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f/scene/gaussian_model.py#L259)で、0.01より濃い粒を0.01にし、それより薄い粒はそのままにします。
- `densify_and_prune` に渡す0.005は削除する不透明度の基準、20は画面上の半径の基準です。画面上の半径が20画素を超えるか、粒の大きさがシーンの広がりの10%を超えるときに「大きすぎる」とみなして削除します。この判定は反復3,000より後だけ行います。
- 勾配の基準0.0002は、画面の端から端までを−1から1とした座標での値です。元の実装は、画素座標での勾配に横は幅の半分、縦は高さの半分を[掛けています](https://github.com/graphdeco-inria/diff-gaussian-rasterization/blob/59f5f77/cuda_rasterizer/backward.cu#L458-L461)。
- 不透明度の学習率は、2023年公開時の実装でもgsplatの例でも0.05です。色の学習率は、次数1以上の係数では20分の1にします。Adamの $\varepsilon$ は1e-15で、PyTorchの既定値1e-8より小さい値です。
- 回転のクォータニオンを使うたびに長さ1にそろえるのは、四つの値をそれぞれ更新すると長さがずれるからです。ずれたまま回転行列に直すと形の伸び縮みが混ざり、スケールと役割が重なります。

## gsplatとの比較

写真、初期値、学習率、損失をすべて同じにして、描画と密度制御だけをgsplatに替えて学習しました。

| | 自作のコード | gsplat |
| --- | --- | --- |
| 保持視点7枚のPSNR | 23.73dB | 23.93dB |
| 保持視点7枚のSSIM | 0.8178 | 0.8185 |
| 30,000反復の学習時間 | 5,947秒 | 222秒 |
| GPUメモリの最大量 | 15.1GB | 0.9GB |
| 学習を終えたときの粒の数 | 387,478個 | 505,879個 |

- 学習を終えた387,478個の粒を同じカメラでgsplatにも描画させると、画素値（0から1）の差は平均0.000009です。どちらも同じ粒からほぼ同じ画像を作ります。
- 約27倍という学習時間の比は学習全体にかかった時間の比で、同じ粒を描画する速さの比ではありません。密度制御も替えたため、粒の増え方が違います。
- メモリの差は逆伝播のやり方から来ます。自動微分は、タイルの画素と粒の組ごとに途中の値を残します。gsplatと元の実装は途中の値を残さず、奥から手前へたどりながら[透過率を $1-\alpha$ で割って](https://github.com/graphdeco-inria/diff-gaussian-rasterization/blob/59f5f77/cuda_rasterizer/backward.cu#L503)一つ手前の値に戻すので、画素ごとに一定のメモリで済みます。
- 一粒が持つ値は59個で、32ビットの浮動小数点数なら236バイトです。学習中は勾配とAdamの二つの移動平均が加わり、一粒あたり944バイトになります。387,478個なら約0.37GBで、15.1GBのほとんどは描画の途中の値です。

### gsplat 1.5.3では不透明度のリセットが働かない

gsplat 1.5.3の `DefaultStrategy` は、[条件式](https://github.com/nerfstudio-project/gsplat/blob/v1.5.3/gsplat/strategy/default.py#L195)が `if step % self.reset_every == 0 & step > 0:` になっています。Pythonでは `&` が `==` より先に計算されるので、この条件はどの反復でも成り立ちません（mainの版では `and` に直っています）。そのため、gsplatの学習では反復3000で保持視点のPSNRが落ちません。

保持視点のPSNRが途中で最も高くなり、その後下がる点はgsplatも同じです。乱数の種を四通り変えて学習すると、保持視点のPSNRは反復2500〜3500で最大の24.5〜25.0dBになり、最後は23.2〜24.0dBでした。どの回でも1.0dB以上下がり、その間も学習視点のPSNRは36〜38dBまで上がり続けました。密度制御を反復5000で止めても、下がり幅は半分ほどになるだけです。粒が増え続けることと、粒の数が変わらなくても写真に合わせ込みすぎることが、半分ずつ効いています。

### gsplatは同じ乱数の種でも結果が一致しない

種0で三回学習すると、最終的なPSNRは22.77〜23.93dBの範囲でばらつきました。上の表の23.93dBは、そのうちの一回の結果です。

## メモリと品質の釣り合いを探すとき

粒の増えすぎを抑えればメモリは節約できますが、細部は表現しにくくなります。反復数、画像の解像度、密度制御の条件のうち、一度に一つだけ変えて同じ視点で見比べてください。一度にいくつも変えると、どの変更で品質が変わったのか分からなくなります。
