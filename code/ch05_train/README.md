# 第5章 train.py：二次元の画像で学習を動かす

第5章の学習（描画して差を測り、勾配で直し、粒を増やす）を、Pythonの標準ライブラリだけで書いたコードです。48×32画素の画像に、平面の丸い粒を当てはめます。カメラへの投影はなく、粒は丸いままで、損失は $L_1$ だけです。数秒から数十秒で終わります。

```sh
python3 train.py
```

## 関数の役割

| 関数 | 内容 |
| --- | --- |
| `teacher` | 教師画像を数式で作る。灰色の背景に赤と青の円があり、黄色の細い線が横切る |
| `activate` | 学習用のパラメータを実際に使う値に直す（対数とシグモイド） |
| `evaluate` | 前半で第4章の合成を行い、後半で勾配を計算する |
| `check_gradients` | 式で計算した勾配を数値微分と比べる。学習の前にまず実行する |
| `adam` | Adamでパラメータを更新する |
| `densify` | 密度制御。薄い粒を削り、位置の勾配が大きい粒を複製か分割する |

中心になるのは、`evaluate` の後半、`adam`、`densify` の三か所です。

### evaluate の後半（逆伝播）

画素ごとに奥から手前へたどります。`behind` が本文の $B_i$、`remaining` が $T_i$ です。$\partial C/\partial \alpha = T\,(c - B)$ に $\partial L/\partial C$ を掛けて `dL_dalpha` を求め、本文の三つの微分を掛けて粒の勾配 `g` に足し込みます。

```python
g[0] += dL_dalpha * alpha * dx / sigma ** 2  # ∂α/∂x
g[1] += dL_dalpha * alpha * dy / sigma ** 2  # ∂α/∂y
g[2] += dL_dalpha * alpha * r2               # ∂α/∂(log σ)
g[3] += dL_dalpha * alpha * (1 - opacity)    # ∂α/∂(ロジット)
```

色の勾配は $\partial C/\partial c = T\alpha$ です。

### adam

勾配を $g$、二つの移動平均を $m$ と $v$、学習率を $\eta$ とすると、Adamの更新は次の式です。

$$m \leftarrow 0.9\,m + 0.1\,g, \qquad v \leftarrow 0.999\,v + 0.001\,g^2, \qquad w \leftarrow w - \eta\,\frac{\hat m}{\sqrt{\hat v} + \varepsilon}$$

$\hat m$ と $\hat v$ は、0から始めた移動平均が初めのうち小さく出る分を補正した値です。コードでは更新回数を `state[2]` に持ち、移動平均を $1-0.9^t$ と $1-0.999^t$ で割っています。

勾配の平均を勾配の大きさにあたる量で割るので、勾配の向きがそろっていれば、勾配が0.001でも1000でも一回に動く量はほぼ学習率と同じになります。Adamは位置のxとyを別々のパラメータとして扱うので、最初の一回はxもyもほぼ学習率と同じ量だけ動きます。そのため最初の一歩は勾配の向きではなく斜めになります。

### densify

不透明度が0.05未満の粒を削ります。位置の勾配が大きい粒は、$\sigma$ が2より大きければ分割し、小さければ複製します。分割では二つとも大きさを1.6で割り、元の広がりの中にずらして置きます。複製では写しを元と同じ場所に置きます。

複製した直後の二つの粒は同じ値を持ちますが、その後は別々に動きます。理由は二つあります。

- **色の勾配が違う**：同じ場所にあっても、重ねる順では一方が手前、もう一方が奥になります。二つの粒の不透明度を $\alpha$、手前の粒に届く透過率を $T$ とすると、色の勾配は手前が $T\alpha$、奥が $T(1-\alpha)\alpha$ です。一方、$\alpha$ の勾配は式 $T_i\,(c_i - B_i)$ に代入するとどちらも $T(1-\alpha)(c - B)$ で等しくなります。
- **Adamの移動平均が違う**：元の粒はそれまでの移動平均を引き継ぎ、写しは0から始めます。同じ勾配を受けても一回に動く量が違い、いったん値がずれれば、その後の勾配も違ってきます。

写しを置く場所は、原論文の記述と元の実装で違います。[元の実装](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f/scene/gaussian_model.py#L441)は写しを元の粒と同じ場所に置き（`new_xyz = self._xyz[selected_pts_mask]`）、離すのはその後の更新に任せています。原論文には写しを「位置の勾配の向き」へ動かすと書かれています。`train.py` は元の実装に合わせました。本文の冒頭のGIFと[ブラウザの実験](https://satoooh.github.io/gaussian-splatting-guide/lab/training/)は原論文の記述に従い、写しを粒が引っ張られる向きへ少しずらして置いています。

`train.py` は、追加した粒では更新回数のカウンタも0に戻します。元の実装はカウンタを粒ごとに持たず、追加した粒にもそれまでの反復数を使います。そのため、反復600で追加した粒が最初の一回に動く量は、元の実装では学習率の約2.1倍になり、`train.py` では学習率と同じになります。

## 値を一つだけ変えて比べる

先頭の `DENSIFY` を `False` にすると、粒は8個のまま増えず、PSNRは15.65dBで止まります。8個の粒だけでは、細い線と二つの円を同時には表せません。

次の四つの変更は、どれも元の21.18dBよりPSNRが下がります。

| 変更 | PSNR | 起きること |
| --- | --- | --- |
| 位置の学習率（`RATES` の先頭の二つ）を10倍の0.8にする | 18.89dB | 一回の更新で動きすぎて、合う位置を通り過ぎる |
| 位置の学習率を10分の1の0.008にする | 18.95dB | 動きが遅く、600回では合わせきれない |
| `densify` の中の0.05を0.5にする | 16.48dB | 育つ途中の薄い粒まで削ってしまい、粒が48個までしか増えない |
| 分割で大きさを割る1.6を1.0にする | 19.26dB | 分割しても粒が細かくならず、細い線に合わせにくい |

同じ流れを三次元の粒に広げたコードは [ch05_train3d](../ch05_train3d/) に、実写の写真で学習するコードは [ch05_real](../ch05_real/) にあります。
