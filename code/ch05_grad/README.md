# 第5章 grad.py：合成の勾配を数値微分と比べる

第5章の式 $\partial C/\partial \alpha_i = T_i\,(c_i - B_i)$ を、Pythonの標準ライブラリだけで確かめるコードです。

```sh
python3 grad.py
```

```text
色: (0.5, 0.0, 0.25)
赤の ∂C/∂α: (1.0, 0.0, -0.5)
L1: 0.15
∂L/∂α（赤、青）: [-0.5, 0.166667]
四つ重ねた乱数の例10通りで、式の勾配と数値微分が一致（最大の差 6.8e-11）
```

## 関数と本文の式

| 関数 | 内容 |
| --- | --- |
| `composite` | 第4章の合成。[tiny.py](../ch04_tiny/) の `pixel` と同じ手順で、並べ替えは済んでいるものとする |
| `gradients` | $\partial C/\partial \alpha_i = T_i\,(c_i - B_i)$。前半のループが $T_i$ を手前から、後半のループが $B_i$ を奥から求める |
| `loss` | 一画素の $L_1$（三つの成分の差の絶対値の平均） |
| `loss_gradient` | $\partial L/\partial \alpha_i$。$\partial L/\partial C$ と `gradients` の結果を成分ごとに掛けて足す |

## 色から損失までを手で計算する

本文は色から $\alpha$ までの段だけを扱いました。損失までつなぐと次のようになります。

第4章の赤と青の例（どちらも $\alpha = 0.5$、背景は黒）で、画素の色は $(0.5,\ 0,\ 0.25)$ です。教師画像のこの画素が $(0.8,\ 0,\ 0.1)$ だとすると、赤は足りず、青は多すぎます。$L_1$ は $(0.3 + 0 + 0.15)/3 = 0.15$ です。

各成分を少し増やしたときの損失の変化の割合は、足りない赤で $-1/3$、差のない緑で0、多すぎる青で $+1/3$ です。これに赤の $\partial C/\partial \alpha = (1,\ 0,\ -0.5)$ を成分ごとに掛けて足します。

$$\frac{\partial L}{\partial \alpha_{\text{赤}}} = \left(-\frac{1}{3}\right) \times 1 + \frac{1}{3} \times (-0.5) = -0.5$$

赤の成分も青の成分も、掛けた結果は負になります。赤の $\alpha$ を上げると、足りない赤が増え、多すぎる青が減るからです。ファイルの中の `assert` は、色、勾配、損失がこの手計算と一致することを確かめています。

## 数値微分との比較

式で求めた勾配が正しいかどうかは、パラメータをほんの少し動かして損失の変化を測れば確かめられます。この測り方が数値微分です。ファイルの後半では、粒を四つ重ねた乱数の例を10通り作り、$\alpha$ を $\pm 10^{-6}$ 動かして測った傾きと式の勾配を比べています。差は最大でも $6.8 \times 10^{-11}$ です。

学習では数値微分を使いません。式を使えば、一回描画して奥から手前へ一回たどるだけで、すべてのパラメータの勾配が求まります。数値微分ではパラメータを一つ動かすたびに描画し直すので、粒が数十万個あると間に合いません。
