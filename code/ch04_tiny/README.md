# 第4章 tiny.py：二つのガウシアンを手前から重ねる

第4章の「重み」と「合成」を、Pythonの標準ライブラリだけで書いたコードです。すでに画面に投影された二次元のガウシアンを二つ置き、一画素ずつ色を計算してPPM形式（画素の値を順に並べただけの画像形式）で書き出します。3DGS全体を再現するものではなく、GPU、球面調和関数、勾配計算、学習は含みません。投影まで含めたコードは [ch04_tiny3d](../ch04_tiny3d/) にあります。

```sh
python3 tiny.py
```

成功すると、同じフォルダに幅192、高さ128の `splats.ppm` ができます。PPMを読める画像ソフトで開くと、青とオレンジの楕円が重なって見えます。`open` に渡した `xb` は、同じ名前のファイルがあると `FileExistsError` で止まる書き込みモードです。二回目はファイル名を `splats-b.ppm` などに変えると、前の結果を上書きせずに比べられます。

## 粒の表し方

一つのガウシアンは、次の値を順に並べたタプルです。色は0から1の値として扱い、色空間の変換は省きました。

- 中心 `mx`、`my`
- 主軸の標準偏差 `sx`、`sy`（どちらも正）
- 回転角 `angle`
- 奥行き `depth`
- 不透明度 `opacity`
- 色 `rgb`

## 楕円の座標で距離を測る（alpha_at）

本文の $d^\top \Sigma^{-1} d$ を、逆行列を作らずに回転と割り算で求めます。画素と中心の差 `dx`、`dy` の回転を戻して、楕円の主軸に沿った座標 `u`、`v` に直し、それぞれの軸の標準偏差で割ります。

$$r^2 = (u/s_x)^2 + (v/s_y)^2,\quad g = \exp(-r^2/2),\quad \alpha = \text{opacity} \times g$$

この `u`、`v` は第3章の画素 $(u, v)$ とは別のものです。`u = sx`、`v = 0` の画素では $r^2 = 1$ になります。

## コードの中の透過率（pixel）

`pixel` は本文の合成の式をそのまま書いたもので、`remaining` が透過率 $T$ です。`sorted` の行が「手前から順に」の処理で、`item[5]`（depth）の小さい順に並べます。色を `result` に足す行で $C$ を、`remaining` に掛ける行で $T$ を更新し、最後に背景を足します。

二つの `assert` は本文の手計算を確かめています。赤が手前のときの色が $(0.5, 0, 0.25)$ になることと、中心の画素で $\alpha$ が不透明度0.5に等しいことです。コードでは青を先に配列に入れていますが、depthの順に並べ替えるので赤が手前に来ます。`blue` のdepthを2から0に変え、期待値を「青が手前」の $(0.25, 0, 0.5)$ に書き換えると、前後を入れ替えた結果も確かめられます。

## 画像を見る前に一画素を確かめる

- **重み**：一つ目の横長の粒を回転角0にして、中心、横へ `sx`、縦へ `sy` ずらした三点で `alpha_at` を呼びます。中心では `opacity`、残りの二点では `opacity × exp(−0.5)` になります（この粒なら0.7と約0.42）。
- **背景**：赤と青の例では最後に残る透過率が0.25なので、白の背景なら結果は $(0.75, 0.25, 0.5)$ です。背景を足し忘れると透明な部分が黒ずむので、背景を明るい灰色にしておくと間違いに気付きやすくなります。
- **透過率の範囲**：各 $\alpha$ が0以上1以下なら、`remaining` は常に0以上1以下に収まり、合成が進むほど小さくなります。
- **画素の中心**：`x + 0.5`、`y + 0.5` で評価しているのは、各画素の中心をサンプルするためです。整数座標で評価する実装とは半画素ずれます。

## パラメータを一つずつ変えて確かめる

1. `sx` だけを半分にして、横方向の広がりが小さくなることを確かめる。
2. `angle` だけを変えて、長軸が回転することを確かめる。
3. `depth` だけを入れ替えて、重なった部分の色を比べる。
4. `opacity` だけを0にして、もう一方の粒と背景だけが残ることを確かめる。

画像が予想と違ったら、中心の一画素に絞って $\alpha$、$T$、色の更新を紙の上で一回ずつ追ってください。`tiny.py` は画素ごとに並べ替えているので効率が悪く、`tiny3d.py` では描画の前に一度だけ並べ替えています。
