# 第8章 sizes.py：値を変えない圧縮でPLYはどこまで小さくなるか

第8章の「値を変えない圧縮では17%しか減らない」の測定に使ったコードです。3DGSのPLYを読み、値を一つも変えずに並べ方だけを変えながらzlibで圧縮して、大きさを比べます。zlibはZIPやPNGに使われている圧縮の方法で、Pythonの標準ライブラリに入っています。

```sh
python3 sizes.py bowl-30000.ply
```

渡すPLYは、すべての値が32ビット浮動小数点数で、リトルエンディアンのバイナリ形式のものです（BrushやGraphDecoの実装が書き出すPLY）。それ以外は `assert` で止まります。

## 出力の読み方

第6章で学習した料理のモデル（bowl-30000.ply）を渡すと、次のように出力されます。

```text
159074粒、一粒236バイト（59個の値）
 37.54 MB   236.0 バイト/粒  100%  そのまま
 35.44 MB   222.8 バイト/粒   94%  そのまま圧縮する
 34.60 MB   217.5 バイト/粒   92%  属性ごとにまとめて圧縮する
 31.80 MB   199.9 バイト/粒   85%  バイトの位ごとにまとめて圧縮する
 31.30 MB   196.8 バイト/粒   83%  近い粒を隣に並べてから同じことをする
```

- **一行目**は、粒の数と一粒のバイト数の掛け算と同じ値です。
- **二行目**は、ファイルをそのまま圧縮した場合です。6%しか減りません。汎用の圧縮は、似たバイトの並びが近くに繰り返し現れるほどよく効きます。PLYでは一粒の59個の値が続けて書かれ、位置の隣に色、色の隣に回転が来るので、似た値が隣り合いません。
- **三行目**（`columns`）では、全粒のxだけ、全粒のyだけというように、パラメータごとにまとめ直しています。
- **四行目**（`planes`）では、さらに4バイトの値の何バイト目かごとにまとめます。浮動小数点数の上の位のバイトは、近い値どうしで同じになりやすいからです。
- **五行目**（`morton`）では、空間で近い粒がファイルの中でも隣に来るように、粒の順番を並べ替えます。位置を各軸10ビットに丸め、三つの軸のビットを交互に並べた番号（モートン順序）の小さい順に並べます。近くにある粒は位置も色も似ていることが多いからです。

四つの工夫を重ねても、容量は83%にしかなりません。学習で決まった値の下の位がほとんど乱数のように並んでいて、zlibが繰り返しを見つけられないためです（本文の図「値を変えない圧縮が効くのは、4バイトのうち最上位の1バイトだけ」）。ほかの可逆圧縮でどこまで縮むかは試していません。

## 値を変えていないことの確認

どの工夫も並べ方を変えるだけです。コードの最後の `assert` は、並べ替えた後の値の集まりが元と同じであることを確かめています。粒の順番は描画のたびに奥行きの順に並べ替えるので、ファイルの中の順番が変わっても描画されるシーンは同じです。

## SPZとSOGの変換についての補足

本文の変換の比較（SPZはNianticのspz 1.1.0、SOGはsplat-transform 3.11.2、どちらも既定の設定）から、本文に載せなかった値です。

- SOGが共有するSH係数の組の数は、splat-transformの `--sh-palette-size` で変えられます。SPZの残りのSH係数の精度（既定では次数1が5ビット、次数2以上が4ビット）も、ライブラリの設定で増やせます。
- 粒が55,963個の別のモデル（同じ写真から7000反復で学習したもの）では、SOGがPLYの15.6%、SPZが10.0%でした。粒が少ないほど、SOGの組の表が全体に占める割合は大きくなります。
- 変換したファイルをPLYに戻して元と一粒ずつ比べたずれは、次のとおりです（シーン全体を囲む箱の対角線の長さは約63）。SPZは位置が最大0.0002、回転が平均0.08度、不透明度が最大0.002、基本の色が平均で256段階中の0.6段階。SOGは位置が最大0.002、回転が平均0.6度、不透明度が最大0.005、基本の色が最大5段階。
- SPZは基本の色も決まった範囲の外を切り落とします。料理のモデルでは、範囲外だった3粒で差が最大約283段階になりました。
